# 딸깍 한글 · 문서(워드) · 시트(엑셀) · 슬라이드(PPT) · PDF · 영상편집 · 이미지 디자인 편집기 기획 (2026-11-19)

dev 캡처 2장(한글 편집기, 딸깍 문서)을 보고 정리했다. 코드: `src/app/components/doceditor/`.

## 0. 전제

- **가운데 편집 영역은 오픈소스 에디터**(한글: 웹 한글 기안기류, 워드: ONLYOFFICE류)라 UI를 고칠 수 없다. 고칠 수 있는 건 **바깥**: 공통 헤더 · 왼쪽 템플릿 패널 · 오른쪽 딸깍 AI 패널.
- 한글과 워드는 **안쪽 에디터만 다르고 바깥은 같다.** 그래서 `DocEditor` 하나에 `kind: "hangul" | "word"`만 바꿔 쓴다.
- 이 프로젝트에는 실제 오픈소스 에디터가 없어서, 가운데는 "에디터가 들어갈 자리" 목업이다(템플릿·AI 결과가 그 자리에 보이도록만).

## 1. 지금(캡처) 문제

### 헤더
1. 도구마다 버튼 세트가 다르다: 한글은 파일 열기·템플릿·딸깍 AI·코멘트·0·기록, 워드는 딸깍 문서·딸깍 AI·템플릿·코멘트·0·공유·기록. **한글엔 공유가 없다.**
2. "코멘트"와 "0"이 따로, 그리고 **안쪽 에디터에도 댓글(워드 "댓글")·공유(워드 "공유")·저장이 또 있다** — 두 줄 헤더 중복(docs/editor-common-header.md "2").
3. 파일 이름이 헤더가 아니라 안쪽 에디터 바에만 있다(제목 없음.hwpx / 문서1 — 저장되지 않음).

### 템플릿 패널 (애매한 이유)
1. **언제 쓰는지가 없다.** 빈 문서든 쓰던 문서든 400px 패널이 늘 열려 있어 편집 영역이 화면의 절반 남짓(AI 패널까지 열면 1/3).
2. **썸네일을 읽을 수 없다.** 실제 서식 스캔을 작게 줄여 글자가 안 보이고, 제목은 아래 2줄 설명과 함께 잘린다(“사내에서 업무 추진을 결재받을 때 쓰는 기안 문서로, 문서번…”).
3. **필터가 형식 기준이다.** 한글 편집기 안에서 [한글 | 문서] 칩 — 이미 한글 편집기에 있는데 형식을 또 고르게 한다. 정작 필요한 "용도"(공문·신청서·보고서·계약서…)로는 못 찾는다. 워드엔 칩이 아예 없다.
4. **누르면 무슨 일이 생기는지 모른다.** 지금 문서를 덮어쓰는지, 새 문서로 여는지, 미리보기가 있는지 알 수 없다.
5. **AI와 따로 논다.** 템플릿을 고른 뒤 "이 서식에 내용 채워 줘"로 이어지는 길이 없다 — 딸깍의 핵심(AI)과 서식이 안 만난다.

참고: Word "새로 만들기 › 서식 파일", Google Docs 템플릿 갤러리, Canva·미리캔버스 왼쪽 템플릿 패널 — 공통적으로 ① 빈 문서일 때 크게 보여 주고 ② 용도별 분류 ③ 미리보기 후 적용 ④ 쓰는 중이면 "새 문서로" 또는 "바꾸기"를 묻는다.

## 2. 결정

### 2-1. 헤더 = 공통 `EditorHeader` 그대로
| 영역 | 한글 | 워드 |
|---|---|---|
| ① 정체성 | ‹ · [한글 아이콘] 한글 편집기 ▾ / 제목 없음.hwpx | ‹ · [워드 아이콘] 딸깍 문서 ▾ / 문서1.docx |
| ② 도구 슬롯 | **템플릿** 토글(왼쪽 패널) | 같음 |
| ③ 패널 토글 | **✨ 딸깍 AI**(글자 버튼) · **💬 코멘트** | 같음 |
| ④ 알림 | 🔔 | 🔔 |
| ⑤ 결과물 | **공유**(주요) · 프로필 | 같음 |

- **공유를 두 도구 모두에 넣는다**(한글에 없던 것). 내보내기·다운로드·저장은 안쪽 에디터가 이미 갖고 있어 헤더에 두지 않는다(중복 금지).
- **헤더에 저장 상태를 두지 않는다.** 안쪽 에디터가 이미 보여 준다(워드 "저장되지 않음"·자동 저장). 두 곳에서 다르게 보이면 헷갈린다.
- **코멘트는 UI 디자인 에디터와 똑같이 넣는다(2026-11-19 변경).** 처음엔 안쪽 에디터 댓글에 맡기려 했지만, dev 캡처처럼 딸깍 코멘트(쪽 위 핀 · "새 코멘트 · 1쪽" · 올리기)를 쓰기로 했다. 아래 "2-4".
- **헤더에 기록을 두지 않는다.** 버전 기록은 아직 없다 — 빈 버튼을 두지 않는다.
- 안쪽 에디터의 공유 버튼은 숨길 수 없으면 그대로 두되, 헤더 공유가 주요 버튼(오른쪽 끝 채운 버튼)이다.

### 2-2. 템플릿 패널 다시 짜기
- **열리는 때**: 새 빈 문서를 열면 자동으로 열린다. 템플릿을 적용하거나 AI로 내용을 만들면 자동으로 닫힌다. 그 뒤엔 헤더 "템플릿"으로 연다. → 쓰는 동안 편집 영역을 빼앗지 않는다.
- **폭 300px**(400 → 300). 2열.
- **찾기**: 검색 + **용도 칩**(전체 · 공문 · 신청·확인서 · 기안·결재 · 보고·계획 · 계약·거래 / 워드: 전체 · 보고서 · 기획·제안 · 회의 · 취업 · 안내문). 형식 칩([한글|문서])은 없앤다 — 지금 편집기 형식의 템플릿만 보인다.
- **카드**: 썸네일 위쪽에 **제목을 크게 박은 종이 미리보기**(실제 스캔이 있으면 그 이미지) + 아래 제목 한 줄. 설명은 카드에서 빼고 미리보기로.
- **맨 앞 "빈 문서" 카드**: 템플릿 없이 시작.
- **누르면 미리보기**(편집 영역 위 큰 창): 큰 종이 미리보기 · 제목 · "이럴 때 써요" · 들어 있는 항목 · 버튼 **[이 서식으로 시작]**(주요) **[✨ AI로 내용 채우기]**.
  - "AI로 내용 채우기"는 서식을 적용하고 딸깍 AI 패널을 열어 입력창에 "「협조 요청 공문」 서식으로 … 내용을 채워 줘"를 넣어 둔다(보내기는 사용자가). → 템플릿과 AI가 이어진다.
- **쓰던 문서가 있으면** 적용 전에 묻는다: **[새 문서로 열기]**(기본) / [지금 문서 바꾸기]. 빈 문서면 바로 적용.

### 2-3. 딸깍 AI 패널
- 공통 `AiAssistantPanel` 그대로(입력창 · 실행 방식 · 프로젝트 자료 · 대화 기록). 한글/워드 예시 문장·추천만 다르다.
- 결과는 가운데 문서에 들어간다(목업: 제목 + 문단). 크레딧은 실제 차감.

### 2-4. 코멘트 (UI 디자인 에디터와 같음)
- 입구는 **상단 바 오른쪽 💬 하나**(2026-11-19 정리, 처음엔 왼쪽 "코멘트" + 오른쪽 💬 둘이었다). 누르면 오른쪽 코멘트 목록이 열리면서 바로 남기기 모드("남길 자리를 클릭하세요 · Esc로 나가기") — Figma 코멘트 도구처럼. Esc나 다시 누르면 패널과 모드가 함께 닫힌다. 오른쪽 패널을 여는 버튼은 오른쪽에(docs/editor-common-header.md 규칙).
- 쪽을 클릭하면 핀 + 새 코멘트(@멘션 · 이모지 · 이미지) → 스레드(답글 · 반응 · 해결 · 삭제 · 되돌리기 · 읽지 않음). 위치 표시는 "1쪽".
- 💬에 읽지 않음 배지. 함께 보는 사람은 공유 팝오버.
- 부품은 `uidesign/Comments.tsx`(CommentPin · DraftPopover · ThreadPopover)와 `editor-shell/CommentListPanel`을 그대로 쓰고, 문서 쪽 레이어만 `doceditor/DocCommentLayer.tsx`. 실제로는 오픈소스 에디터 위에 겹친 레이어라 글자 범위가 아니라 쪽 좌표에 붙는다(글자를 고치면 핀 위치가 어긋날 수 있다 — 실제 연동 때 에디터 댓글 API와 맞출지 결정).

### 2-5. 템플릿 버튼 위치 (2026-11-19 판단: 지금 자리 유지)
- 헤더 왼쪽 도구 슬롯(파일 이름 옆)에 둔다. **왼쪽 패널을 여는 버튼은 왼쪽, 오른쪽 패널(AI·코멘트)을 여는 버튼은 오른쪽** — 버튼과 열리는 패널이 같은 쪽이라 찾기 쉽다(Google Docs 개요 아이콘도 왼쪽).
- 템플릿은 이 도구에만 있는 기능이라 공통 버튼(AI·코멘트·공유)과 섞지 않는다 — 헤더 규칙의 "② 도구 슬롯" 자리.
- 코멘트를 오른쪽으로 합쳐 왼쪽엔 템플릿만 남아 역할이 분명해졌다.

### 2-6. 엑셀(딸깍 시트) — 같은 셸, kind "excel"
- 헤더·템플릿 패널·딸깍 AI·코멘트·공유는 한글·워드와 같다. 다른 것만: 파일 `통합 문서1.xlsx`, 용도 칩(회계·세금 · 보고·분석 · 일정·관리 · 거래·견적 · 인사·급여), 템플릿 11개(실제 서식 이미지: 일일 업무 보고 · 마케팅 결과보고서), 가운데는 시트 목업(열 A~L · 행 번호), 코멘트 위치 "Sheet1".
- AI 결과는 1행 제목 + 3행 머리글(열). 요청에 "열: …"이 있으면 그 열을 그대로 쓴다.

### 2-6b. PPT(딸깍 슬라이드) — 같은 셸, kind "ppt"
- 파일 `프레젠테이션1.pptx`, 용도 칩(사업·제안 · 보고 · 교육·강의 · 회사·서비스 소개 · 행사·홍보), 템플릿 10개(실제 이미지: 사업계획 발표자료 · 트렌드 리포트 · 플랫폼 소개), 16:9 미리보기.
- 가운데 목업: 왼쪽 슬라이드 목록 + 16:9 슬라이드. 코멘트 위치 "1번 슬라이드".
- AI: 요청에 "N장"이 있으면 그 장수가 이긴다(템플릿 구성을 앞에서부터 쓰고 모자라면 "추가 n"). "자세히 적어서 요청하기"는 무엇을 발표* · 꼭 넣을 내용 · 듣는 사람 · 장수(5·10·15장) → [슬라이드 만들기].
- 공통 수정(2026-11-19): AI 입력창의 실행 방식 메뉴(자동 / 계획 먼저 보여 주기)가 패널 오른쪽 밖으로 잘리던 것을 입력창 폭 안으로. 설명도 "바로 캔버스에 그려요" → "보내면 바로 작업해요"(문서·시트·슬라이드 공통).

- dev 딸깍 슬라이드 캡처 반영(2026-11-19): 템플릿은 **1열 큰 미리보기**(16:9를 2열로 두면 너무 작다), 헤더 ▷ **발표 (F5)**(dev는 안쪽 에디터의 "발표" 버튼 — 공통 헤더 ⑤ 결과물 자리로), 슬라이드 아래 "클릭하여 노트 추가" 자리.

### 2-8. PDF(딸깍 PDF) — 같은 셸, kind "pdf", **템플릿 없음**
- dev 캡처에는 PDF에도 템플릿 패널([PPT | 문서] 칩)이 있지만 뺐다. PDF는 새로 만드는 도구가 아니라 **이미 있는 파일을 열어 고치는 도구**라 템플릿이 맞지 않는다. 그 자리(헤더 도구 슬롯)는 **[열기]**.
- 첫 화면: "고칠 PDF를 열어 주세요" + [PDF 파일 열기](끌어다 놓기 가능). 파일을 열기 전엔 헤더에 파일 이름·공유가 없다(공유할 것이 없음).
- 열면 가운데에 실제 PDF(브라우저 PDF 보기, 목업 대신 진짜 파일). 코멘트 위치 "1쪽". 연 파일은 이 탭에서만(저장 안 함).
- 딸깍 AI: 요약 · 번역 · 표를 엑셀로 · 개인정보 가리기. "자세히 적어서 요청하기"는 무엇을 할까요*(칩) · 범위 · 덧붙일 요청 → [실행하기]. 파일을 열기 전에 시키면 "먼저 PDF를 열어 주세요". 결과는 목업 문장, 크레딧 20.
- 홈 "PDF"와 앱 전환 격자의 PDF "준비 중"을 풀었다.

### 2-9. 영상(딸깍 영상편집) — kind "video"
- dev 캡처대로 **코멘트·공유 없음**(딸깍 AI · 템플릿만). 헤더 규칙 "4"에 따라 공유가 없으니 **[내보내기]가 오른쪽 끝 주요 버튼**.
- 템플릿 7개(세로 9:16, 실제 이미지 4개: 숏폼 홍보 · 제품 광고 리뷰 · 집중 공부 브이로그 · 커뮤니티 게시글 스타일), 용도 칩(광고·리뷰 · 브이로그·감성 · 정보·커뮤니티 · 행사·홍보).
- 가운데 목업: 미리보기(9:16) + 타임라인(장면 블록). AI: 장면 나누기 → 자막·음악 → 타임라인에 넣기.
- "자세히 적어서 요청하기": 무엇을 만들까요* · 길이(15·30·60초) · 화면 비율(9:16·16:9·1:1) · 꼭 넣을 자막 → [영상 만들기].

### 2-10. 이미지(이미지 디자인) — kind "image"
- dev 캡처처럼 코멘트·공유 있음. 템플릿 8개(1:1, 실제 이미지 4개: 기획전 홍보 · 간식 추천 · 트렌드 · 홈트 카드뉴스), 용도 칩(광고·프로모션 · 카드뉴스 · 썸네일·배너 · SNS 게시물).
- 가운데 목업: 1080×1080 캔버스. 코멘트 위치 "1페이지".
- "자세히 적어서 요청하기": 무엇을 만들까요* · 크기 · **분위기**(dev 브리프의 분위기 칸은 이미지에서만 의미가 있어 여기에만 둔다) · 꼭 넣을 문구 → [이미지 만들기].
- 홈 "영상"·"이미지" 아이콘은 이제 예전 빈 템플릿 워크스페이스가 아니라 이 편집기를 연다(레이어 분리 미니 에디터는 그대로).

### 2-7. "브리프" → "자세히 적어서 요청하기"
- dev 캡처의 "브리프"는 **빈칸(주제·핵심 내용·누구에게·분위기·꼭 넣을 문구·로고)을 채우면 요청 문장을 만들어 주는 양식**이다. 입력창에 그냥 쓰는 것과 목적은 같고, 무엇을 써야 할지 모르는 사람을 돕는다.
- 문제: ① "브리프"라는 이름이 낯설어 무슨 기능인지 모른다(사용자 피드백) ② 모든 도구에 같은 칸이라 시트에 "분위기(귀여운·고급스러운)"·"로고·사진"처럼 상관없는 칸이 있다 ③ 헤더에 상시 버튼이 하나 더 생긴다.
- 결정: 이름을 **"자세히 적어서 요청하기"**로, 자리는 **AI 패널 첫 화면 카드**(대화를 시작하면 사라짐), 칸은 도구마다:
  - 한글·워드: 무엇을 쓸까요* · 꼭 들어갈 내용 · 받는 사람 · 말투(공식적인·공손한·간결한·친근한) → [문서 쓰기]
  - 엑셀: 무엇을 정리할까요* · 들어갈 항목(열) · 기간·범위 · 계산(합계·평균·전월 대비·비율) → [표 채우기]
- 보내면 칸 내용을 요청 문장으로 바꿔 대화에 그대로 보인다(무엇을 시켰는지 남는다). 구현: `AiAssistantPanel`의 `brief` 옵션(`BriefConfig`).
